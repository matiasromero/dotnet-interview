Sync Tick Lifecycle

Five phases per tick. Independent try/catch. Push first, pull next, retention last — and a failure in one phase never aborts the next.

TL;DR — operational
  • Phase 1 · 2 push: drain the OutboxEvents queue, POST/PATCH/DELETE to the external (FIFO, capped by OutboxBatchSize)
  • Phase 3 · 4 pull: GET external, reconcile each entity via last-write-wins, mirror-cascade external deletes
  • Phase 5 retention: bulk-delete processed OutboxEvents older than OutboxRetention; skipped when ≤ 0
  • Isolation each phase has its own try/catch — a transient external failure in phase 1 still lets phase 3 discover remote changes

§01 The 5 phases at a glance

Each phase has a distinct responsibility, a distinct failure mode, and a distinct cardinality. They run in fixed order so that local intent flushes before remote state is reconciled — the retention cleanup is a separate concern that does not depend on the previous four.

§02 The flow of a tick

The five phases run sequentially under SyncBackgroundService.ExecuteAsync. Each phase is wrapped in its own try/catch so that a fault in one does not cancel the next. §03 Why isolated try/catch — not a single one

The five phases are conceptually independent. A transient external failure during Phase 1 (network blip, circuit breaker probing) must not prevent Phase 3 from discovering remote changes during the same tick. Three reasons compound:

Independent failure domains

Push depends on the external accepting writes. Pull depends on the external answering reads. Retention depends on the local DB. A single try/catch would make the slowest/least reliable subsystem block the others.

Push and pull self-heal each other

If a push POST crashes mid-write, the pull's adopt by source_id recovers on the next tick — but only if pull actually runs. Tying both inside one try/catch breaks the safety net.

Retention is housekeeping

A failure in Phase 5 is operationally irrelevant — the table grows by one tick's worth of events. Treating it as critical would mask the real issue (sync) under noise.
